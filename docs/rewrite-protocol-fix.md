# 中文改写输出协议修正

日期：2026-09-12。范围仅限通用改写协议、诊断及兼容检查点，不调整博客提取规则或阅读器展示。

## 问题与修改

SDLC 文章的旧任务共 16 节，已保存 2 节，第 3 节触发段落标记校验。失败响应未保存，不能断言此前具体缺少哪个标记。代码中存在“不输出内部 ID”和“必须保留 B 标记”的矛盾指令，且将多种协议失败合并成同一句提示。

新协议消除上述冲突，使用简短的正文块边界，源文本存在标记碰撞时才增加命名空间。资产仍使用源内容绑定的保护标记。只剥离完整包住首尾预期块的 Markdown 围栏，随后继续逐块校验；缺块、重复、乱序、额外正文、空块、结构变化和资产损坏分别报告程序生成的诊断类别。错误包含失败节号，不保存失败模型正文，不增加自动审阅或重试调用。

协议版本从 7 升至 8。此次仅改变输出封装，内容转换、分节和原有成功输出的语义未变化，因此显式兼容同一原文指纹、标题、地址和模型设置下的 v7 成功检查点。之后保存为 v8，不重新生成已完成分节。其他版本不自动兼容。

## 验证

- `npm test -- test/rewrite`：10 个文件、92 项测试通过，约 2.6 秒。包括普通段落、标题、嵌套列表、表格、代码、公式和链接、围栏处理、标记碰撞、各类损坏、失败分节不落盘，以及 v7 检查点兼容。
- `npm run build`、`git diff --check` 通过。
- 用户授权的真实 DeepSeek 验证：以正常受限正文管线取得《The AI-Native SDLC playbook》第 3 节，共 24 块、4,844 字符；`deepseek-v4-flash` 一次调用成功，约 5.6 秒，生成 2,415 字符中文，24 块全部通过结构与资产校验。检查了实际输出，代码块、列表、标题与文字链接均保留。
- 测试只发送该节，未重新生成整篇，未把测试结果或新检查点写入用户数据库。临时结果留在本机临时目录，不提交原文或生成稿。
- 本次未修改共享原文提取、净化或前端样式，故不重复全来源在线抽检和视觉审计。实际模型验收覆盖失败节，不代表已经完整生成其余 13 节，也不能保证以后模型绝不违反协议。

## 后续修正：v9 资产表示与单向块边界

用户继续遇到 B44 asset-marker 错误后，发现上一轮真实测试把第三节作为独立输入重新编号，未携带前两节衔接上下文，不能代表实际续写。此次使用数据库只读快照中的真实检查点、正常正文管线和原始 B43–B66 编号验证。用户报告的那一次 B44 响应没有留存，不能断言其具体缺失内容；后续真实响应确认了两种协议脆弱性：模型把部分块的结束标记写成重复开始标记，以及把 B49 代码占位符展开为与原文完全相同的代码，却被判定资产丢失。

- 每块只保留开始标记，最后输出一个整节结束标记；仍检查缺块、重复、顺序、结构和尾部多余内容。资产使用所属块的简短编号，源内容完整性仍由持久化指纹核对。
- 完整代码、公式、图片等不可改写块由程序原位恢复，只向模型提供理解上下文，不要求其输出。纯资产分节不调用模型，并遵守取消与检查点门禁。
- 对混合正文块，允许同块内数量和原始内容严格一致的 Markdown 资产表示；行内代码仅按 Markdown 解析语义容忍等价反引号/空格。改名、普通文字猜测、重复资产、跨块代码复制仍失败。链接目标仍由程序恢复，模型只改写锚文本。
- 错误补充资产 ID、种类和固定原因，不记录响应正文。v9 显式兼容同输入和模型设置的 v7/v8 成功检查点；不增加自动模型重试或审阅。

验证：10 个相关测试文件共 108 项通过；随后新增纯资产分节取消用例，该文件全部 14 项通过（总用例增加到 109 项）。最终 `npm run build`、`git diff --check` 通过。保存的 B49 失败响应在新资产恢复器下原样回放，24 块全部通过且代码与原文一致。最终真实续写由 2 个检查点续至第 3 个，第三节一次 DeepSeek 调用通过，在第四节请求前停止；测试检查点仅留内存，未写用户数据库。未重新生成全篇，未重复无关的在线来源/视觉审计。此次规则同时写入 AGENTS.md。
