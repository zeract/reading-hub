# 改写响应封装与有限恢复

## 当前契约（2026-10-23）

模型响应必须是完整 JSON，或单个完整 JSON/无标签 Markdown 外围围栏。解释文字、多个对象、截断和猜补仍被拒绝。引用的数量、开闭形式、源父级及资产目标均由程序校验，不根据译文猜测链接归属。

文字节点的独立契约解析器区分缺失、重复、未知 ID、记录形状、文本类型、文本长度与响应形状。重复节点的所有候选都被排除，不挑选第一份或最后一份；输出顺序不必等于原文顺序，但 ID 必须逐字匹配，程序不补后缀、猜归属或接纳额外记录。

每节先解析全部收到的文字节点，再收集每个坏段落的第一条引用诊断，与能确定归属的节点错误合并，包括需要整节恢复的响应中已知节点的引用诊断。仅将受影响的完整段落交给同一个局部修复请求，成功段落保持不变。

未知 ID 或无 ID 记录同时伴有缺失源节点时，恢复目标是全部缺失源节点及已查出的坏段落：丢弃不可归属的记录，从原文重新生成这些确定的目标，不将未知文字猜配给任何 ID。不能只丢弃错误记录后把剩余结果当作完整成功，必须收到替代节点并重新严格校验。没有缺失源节点时，额外记录无法对应安全的局部目标，才从当前节原输入重新请求一次；响应形状或 JSON 错误也重试当前节。此前已完成的节不重发。

修复响应必须重新通过完整校验，含错误的中间文档不能返回或保存。不得先修第一个坏段落，再因其他坏段落耗尽预算而失败。

`repair.issues` 只包含程序生成的段落 ID、已知引用 ID（或 unknown）与固定错误类别，不包含模型正文。模型从受影响段落的原始输入重新改写，不接收坏响应。提示明确引用移动单位是完整子树：并列引用分别闭合，子引用不能脱离原父级，闭合标记与当前栈顶一致。

JSON 格式、节点协议错误的整节重试及段落/引用局部修复共用每节一次预算，第二次出现其他类别也不增加预算。错误包含程序 ID（无法确定时 unknown）及固定类别，不再合并成“缺失、重复或超出长度”。传输失败、供应商截断及传输大小限制不进入协议修复；取消后不保存迟到响应；修复仍失败则停止，保留已成功分节与旧稿。

本次未改变输入源树、段落切分、指纹、输出 schema、长度上限或资产校验语义；引用说明与 ID 必须原样复制的说明只是明确既有规则，恢复调度覆盖全部完整响应协议错误。因此保留原提示版本与匹配的 v12/v13 检查点，不导致已验证分节重新生成。不修改用户数据库。

## 结构化局部修复封装（2026-10-24）

普通首次生成与检查点仍使用原有文字/引用标记。唯一一次局部修复请求的输入与输出改用 `blocks[{id,parts}]`：parts 是文字字符串、`{ref,parts}` 格式/链接子树或 `{ref}` 不可编辑资产。输入直接从源树生成，包含完整段落及原始 ID，避免让模型先解析文字标记再重建引用。模型在同一完整段落内改写语言并选择引用子树的位置；程序依据原引用类型序列化完整开闭标记，随后执行原有数量、嵌套父级、链接非空与资产校验。不在段尾追加闭合符、不猜测缺失链接范围。未知 ID、跨段引用、重复、资产改型、空链接、额外字段、残缺 JSON 和第二次失败仍拒绝，错误不包含模型未知 ID。

此变更仅澄清修复响应封装，源树、分节、内容校验、patch 持久化格式和 v12/v13 检查点身份不变；已有成功分节继续严格复用。修复器仍严格接受完整且有效的旧 `text` 响应，不能把错误旧响应自动补成有效结果。历史 text-nodes v11 不启用该封装；不增加模型调用预算或文章特例。
