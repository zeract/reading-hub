# AI 改写兼容性评估

核实日期：2026-09-09。本次评估未新增模型调用或改写入口。

## 结论

可以加入，适合作为用户主动生成的独立阅读版本。Reading Hub 的原文、收藏、发布时间及收集时间不应因改写发生变化。优先做忠实重述和技术解释，而不是直接采用参考项目的作者人格、开头吸引注意或延伸结论等写作要求。

## 参考实现及差异

[QMReader 的改写实现](https://github.com/joeseesun/qmreader/blob/main/lib/deepseek.js)使用按材料类型选择的提示词，将正文、图片及链接作为输入；正文最多发送 14,000 字符。它对材料与提示词标识做哈希缓存，生成后检查中文长度和段落数，再保存独立改写版本及模型信息。这些检查可以发现空回复或明显不完整的结果，不能证明事实、数据或公式忠实。

[服务入口](https://github.com/joeseesun/qmreader/blob/main/server.js)还提供自动改写和公开资产展示。这部分与本项目按需调用、本地保存及受限上下文的设计不同，不建议整体移植。

## 建议接入方式

1. 阅读工具栏增加“AI 改写”，由用户选用已有服务后主动发起；原文与改写可以切换，生成时支持取消和失败重试，不阻塞订阅同步。
2. 复用 AiService 的 Keychain 配置、窗口请求归属、取消和输出预算。当前文章上下文上限为 18,000 字符；材料超限时明确显示“片段改写”，不能宣称全文改写。分段全文处理应另行设计，不扩大现有边界作为捷径。
3. 原文不覆盖，结果标注为 AI 生成；保留关键数字、限定条件、链接与公式，不自行补充事实。沿用安全 Markdown / 公式渲染和图片代理，模型输出不能生成任意网络权限。
4. 第一阶段可只在当前阅读会话显示。若要跨重启保存，再建立独立派生版本表，记录文章身份、输入哈希、提示词版本、模型和生成时间；不能借用摘要、原文或同步时间字段。缓存身份需要包含模型与提示词版本。

本地持久化改写会改变当前“AI 对话只在会话内”的约束，应作为明确的新功能实施并测试；此评估不隐式启用后台生成或公开发布。
