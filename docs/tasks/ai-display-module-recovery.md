# 任务：AI 显示模块恢复与失败状态排版

状态：完成

## 目标与范围

- 修复开发版 AI 回答显示模块加载失败；隔离验证进程与实际开发服务的依赖缓存。
- 加载中或失败时仍显示安全的纯文本回答；问题卡片不重复显示错误和重试按钮。恢复显示不重新请求模型，不丢失流式文本。
- 失败状态沿用共享按钮与字体令牌，检查窄/默认/宽窗口、125% 缩放以及划词回答。
- 不变更模型、提示、密钥、数据库、原文提取或正文管线；不调用真实模型。

## 根因与契约

- 2026-10-06 22:35 CST 开始调查，工作区干净。
- 独立 Electron 窗口复现：当前 Vite 服务的 AI 模块及共享 Markdown 模块均 HTTP 200；`markdown-it.js` 和 `katex.js` 请求均 HTTP 504，状态为 `Outdated Optimize Dep`。没有调用模型或读取文章库。
- 服务响应使用的依赖版本与磁盘 `.vite` 元数据不一致，且磁盘元数据只有 React 依赖。`renderer-bundle.test.ts` 的开发服务器复用默认缓存并关闭依赖发现，可能与正在运行的服务互相覆盖。自定义延迟模块地址不进入普通依赖扫描，首次显示才发现解析库。
- `DeferredAiMarkdownContent` 原实现丢弃可见文本，只显示无样式错误；按钮没有共享类，错误段落继承界面根字号与浏览器段距。问题和回答共用该模块，导致两条重复失败提示。
- 本次保持生产按需加载及已知本地模块 URL 的重试机制；只做本机模块恢复，不加载远端脚本或执行模型 HTML。
- 23:00 CST 截图发现划词卡片被右边界裁切：锚点只在首次选中时求值，未跟随窗口、字号和阅读列变化。保留临时 DOM Range，以 resize/正文尺寸变化重新计算坐标，维持原请求身份；阅读区滚动仍按现有行为关闭划词。真实窗口断言增加屏幕边界，而非只检查按钮在卡片内。
