# 任务：架构审查后的执行边界与资源生命周期修复

状态：实现及验收完成；提交和运行实例见当次交付消息。

## 目标与范围

- 正文提取、净化、公式及结构转换移出 Electron 主线程；保持来源身份、净化、数学语义和安全边界。
- 消除重复分页刷新，稳定动态高度列表插入、删除和内部重排的滚动锚点。
- 用户标记、来源操作、同步原子批次及改写检查点统一经存储线程提交。
- 完善受限原文窗口的有界、隔离、可回收生命周期；协调当前原文/语言/改写/封面资产归属；默认只读取结构树。
- 不新增产品 UI，不调用真实模型，不扫描清理历史库，不扩展远端采集。用户已授权提交并推送 `zeract/reading-hub` 的 `main`；起始工作区干净，HEAD `9b3d914`。

## 根因与契约

- `ArticleReader` 直接运行同步准备、净化和 MathJax；原来的 `awaitWithAbort` 只停止等待。现在独立单转换线程、有界队列、前台优先、阶段/公式取消、120 秒执行预算与 30 秒空闲回收；不会因本地繁忙/故障再启动浏览器抓取。
- 通知 dirty 与刷新完成的 revision 脱节；现在通知和轮询合并最大目标，显式刷新已满足的目标不重复读全部分页。分页使用一次累积去重。
- 列表只按估计高度恢复一次；现在边界变化使用虚拟器原生锚点，内部等长重排保持行内偏移的 index target。原生回归等待连续动画帧几何稳定，保留测量轨迹。
- SQLite 写锁会阻塞主线程；现在宿主列举语义 RPC、共享串行 WAL 写线程。同步提交只有一份实现，卡片、Feed 正文、归属、任务覆盖、验证器和检查点保持一个立即事务。删除、状态、检查点、来源维护均迁移；失败退出仍排空并关闭存储线程和主侧元数据连接。
- 原文窗口随机 session 仅清理 storage；现在使用临时 profile 辅助进程，2 活动/8 等待，四类原生清理，卡死回收，macOS accessory 身份及 Cmd+Q 交还宿主。
- 正文替换只增加媒体且读取同时复制树与 HTML；现在读取默认只树，HTML 按消费者惰性派生。当前所有有效版本和封面共同拥有图片；未知版本/无效来源禁止推测性删除，但不阻止新增已证明的合法归属；非法元数据封面单独忽略。
- 无 schema 版本或正文/改写内容协议变更。长期契约见 [architecture.md](../architecture.md)。

## 受控性能与剩余建议

两个独立临时 Electron 进程，在同机、20 公式预热后，分别以基线 `9b3d914` 与当前实现重复处理 300 公式（82,623 字节）三次：

| 指标 | 基线 | 当前 |
| --- | --- | --- |
| 转换时间 | 602–649ms | 683–715ms |
| 0ms 定时器实际延迟 | 603–658ms | 0–2ms |
| 第三次转换后的主进程 footprint | 497.2MiB | 366.1MiB |
| 30 秒空闲点 footprint | 143.7MiB | 282.1MiB |

主循环响应明确改善，转换吞吐略慢，30 秒空闲点内存更高；不据此宣称整体内存下降。主进程 footprint 已包含工作线程，不重复相加；点采样不是精确峰值。当前实现另做有限回收观察：两轮各三次 300 公式、每轮等待生产 30 秒空闲退出，footprint 311.3/319.6MiB，JS 堆 9/10MB；再额外空闲 30 秒后 footprint 回落到 70.0MiB（初始 35.2MiB，无强制 GC）。这是延迟物理回收的一次有限观察，不能拿不同空闲长度与基线混比，也不证明长期无泄漏。1024MiB 是转换线程 V8 老生代限额，不是进程总内存保证。

AI 流式公式缓存和图片解码像素预算没有在本轮实现：缺少真实帧率收益或不损害清晰度的统一阈值证据；本轮不新增缓存或降低图片质量。正常真实库长期运行和物理分配高水位仍需持续观察。
