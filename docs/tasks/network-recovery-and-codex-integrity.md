# 任务：断网恢复与本机 Codex 安全启动

状态：实现与验证完成

## 目标与范围

- 网络恢复后，因 robots 规则暂时不可达而失败的自动信源能重新检查规则并继续同步；仍不得在规则未知时读取正文。
- 本机 Codex 的原生可执行文件签名无效时，不再反复启动并触发 macOS 安全弹窗；用户重新安装有效版本后可恢复。
- 不清除用户数据、系统隔离属性或绕过 Gatekeeper。

## 根因与契约

- `RobotsPolicy` 将网络失败的未知规则缓存一小时，`SyncManager` 同时按失败次数指数退避，网络恢复后仍可能被旧状态阻塞。
- 本机 `/usr/local/bin/codex` 指向 npm 启动脚本，其 arm64 原生文件的 `codesign --verify --strict` 返回 `invalid signature`；当前发现逻辑只检查执行权限。ChatGPT.app 内的启动入口现为 `Resources/codex-cli/bin/codex`，旧路径已失效；当前内置原生文件也未通过同一只读校验。校验失败不能单独证明恶意代码，但不能安全启动。
- 修复须区分网络不可达与站点响应 429/5xx，并保持后者限流退避。
- 网络失败的 robots 缓存缩至一分钟；自动来源在联网状态变化后重新检查，漏过状态变化时 robots 与普通 HTTP 传输失败的来源仍以五分钟为上限重试。HTTP 429/5xx 保留原有一小时 robots 缓存与来源退避。
- macOS 先解析 npm 或桌面应用启动器到原生文件，再核验签名；只执行通过检查的原生文件，不执行未经检查的 shell/JavaScript 启动器。文件属性变化会使签名缓存失效。

## 实施与验收

| 预期行为 | 验收方法 | 结果 |
| --- | --- | --- |
| 网络恢复后重新验证 robots 并自动同步 | 确定性离线/恢复测试 | 通过；覆盖联机事件和错过事件后的到期重试 |
| HTTP 429/5xx 不因恢复事件过早重试 | robots 与调度测试 | 通过；503 缓存不被清除，429/500/503 原退避测试通过 |
| 无效签名的 Codex 不被启动、有效版本可恢复 | 原生命令发现测试与本机只读签名检查 | 通过；无效文件被拒绝，模拟有效安装通过；本机两份原生文件当前校验失败 |
| 代码与安全门禁 | 相关测试、`npm run build`、`git diff --check` | `npm run verify` core 全部通过（含测试、构建、样式契约） |

## 2026-09-26 后续修正：暂时性 robots 服务器失败

状态：本地验证完成，待用户实际断网/恢复回归。

- 用户仍看到旧的“暂时无法确认”提示。复查发现这条消息对应 429/5xx 的通用分支；先前仅缩短了网络异常分支。`net.isOnline()` 未必经历可观察的离线→在线状态变化，因此 5xx 被缓存一小时，来源反复命中旧失败状态。
- 新契约：5xx 的未知 robots 规则五分钟后重新检查，来源同步失败期限也至多五分钟；确有离线→在线变化时可立即重新检查。429 用独立错误身份与提示保留一小时冷却。规则仍未知时绝不读取页面。启动时将旧版模糊错误记录的较长期限至多提前至五分钟后复查一次；不移动已有更早期限，也不影响新版明确识别的 429。
- 验收：真实缓存过期边界、在线状态始终为 true 的后台自动重试、旧记录重新排期与新版限流隔离；只用离线夹具，不访问真实用户来源。历史错误尚无法反推出当时是 429 还是 5xx，因此旧记录仅作一次有界复查，之后按新错误类型退避。
