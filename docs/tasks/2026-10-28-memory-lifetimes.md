# 隔离渲染与阅读器内存生命周期

状态：实现及验收完成；2026-10-28。

目标：修复随机隔离会话累积、后台渲染无全局并发门禁、长文图片离屏后不释放、Base64 跨线程/IPC 重复复制以及改写正文的重复派生/轮询。保留本地原文与图片、安全检查、登录隔离、取消与退出排空，不增加界面或模型请求，不改变用户数据。

前一轮实际诊断：运行约 3 天，主进程 footprint 约 1.5 GB、阅读窗口约 1 GB，主进程约 1280 线程。独立 Electron 80 次空白会话实验：随机会话私有内存 +47.5 MiB，固定会话 +1.7 MiB；clearStorageData 后 800249 字节 HTTP 缓存仍在，clearCache 后归零。阅读窗口的完整组成未做堆快照，不能把 1 GB 全归因于图片。源码确认观察器首次相交后断开，Data URL 留在 DOM，只有切换正文才清理。

实现契约：全局有限隔离会话池，排队/取消有界，清理完成才复用；清理失败不得复用脏会话。正文提取继续使用必要脚本样式及 robots/逐跳验证，优先移除明确无用的媒体预取。图片保留原始本地字节，前台二进制传输为 Blob，远离视口释放并保留布局占位；返回时从本地恢复，放大预览独立持有，迟到响应不重建旧图。改写进度只传元数据，完成时读取一次正文，版本未显示时不提前派生 HTML。

验收：本地取消/失败/复用/隔离/退出回归；真实 Chromium 会话重复操作与跨来源 Cookie/存储隔离；多图滚动、返回、版本切换、预览及零网络重启；全量测试、构建、视觉和受影响来源审计；最终真实库进程与修复前指标分别报告，不以独立夹具下降百分比冒充整机降幅。阶段时间及限制在此持续更新。


实际实现：`RenderSessionPool` 使用 2 个固定内存会话、32 个等待位置；取消/失败后清理继续持有槽位，5 秒清理失败关闭借用，退出排空已启动清理。公开渲染阻止音视频预取，其余提取、安全代理、robots、重定向和权限契约不变。已存图片通过字节跨工作线程及 IPC，在阅读窗口用 Blob；首次远端下载仍兼容现有有界 HTTP 图片管线。原文与改写共用 4 并发、实际阅读滚动区的 300px 预取/1200px 保留区、迟到结果丢弃及预览独立引用。进度读取避开结果/检查点字段；只在显示改写时派生 HTML。数据格式及用户正文未迁移、未删除，未调用模型。
