# 任务：内容身份冲突与连接器能力契约收敛

状态：已实现并完成本地验证；旧库别名迁移另行设计

## 目标与范围

- 用户可观察的预期行为：不同身份不得因共享 URL 相互改写；遗留库中同一稳定身份已对应多张卡片时，新同步不得制造第三张，也不得阻断同批其他有效文章。只有连接器明确获准的身份命名空间才能跨 URL 合并；共享卡片不得被后来的来源静默接管元数据。
- 本轮不包含：猜测并合并旧库冲突行、重建 `entries` 唯一键、改变阅读器/样式、永久隔离可恢复失败来源、限制合法跨站文章链接。
- 已确认的限制：保持旧数据库可读；旧冲突只诊断并跳过，不修改用户既有卡片；维护和阅读访问控制仍由宿主执行。

## 根因与契约

- `isStableContentIdentity` 用任意 `prefix:value` 正则决定跨 URL 合并；`saveEntries` 在 `identityMatches.length > 1` 时仍插入，且 `byUrl` 命中时跳过其它身份匹配并可能覆盖旧 `canonical_identity`。
- manifest 的 `capabilities` 未被宿主读取，和真实的 `sourceCapabilities(kind)` 是两个真相源；`entryPolicy` 和 `requiresAccount` 则已有执行路径。
- 跨来源同 URL 或稳定身份合并时，现有 upsert 会让后来来源覆盖标题、摘要和提供方字段；`original_url` 实际不会更新，来源地址在 `entry_origins` 中保留。
- 已限定 URL 身份升级：仅当同 URL 旧卡片的身份是该 URL（兼容历史 `url:` 写法）、且没有另一行拥有新权威身份时才升级。历史别名与多身份图、`content_hash` 产品语义仍需独立设计；不会猜测合并旧库冲突行。
- 提供方 ID 的命名空间在内置注册表中登记所有者；DOI/arXiv 是允许跨提供方声明的公开标准标识。宿主只在连接器声明授权时按该身份桥接，未声明的字符串退回 URL 身份。
- 当前有效设计见 [聚合器设计评审](../aggregator-design-review.md)。
