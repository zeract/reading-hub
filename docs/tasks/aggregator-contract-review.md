# 任务：聚合器评审校正与确定性缺陷修复

状态：完成

## 目标与范围

- 用户可观察的预期行为：内容 URL 中有身份意义的 `ref`、`source` 和 hash 路由不被全局规范化误删；直接 RSS 与网页发现的 Feed 在入库时遵循同一招聘目标过滤规则；两个来源给出同一显式稳定内容 ID、但不同阅读 URL 时，新采集只出现一张卡片。移除无执行力的 manifest `allowedHosts`，避免误把它当作安全白名单。
- 本轮不包含：旧库中已有重复卡片的自动合并、多身份别名迁移、数据库唯一键迁移、永久停用失败来源、第三方插件或新 UI。
- 已确认的决策与限制：保留明确跨站文章链接；永久删除记录不能因数量上限而使文章重新出现；网络恢复仍允许自动重试。

## 根因与契约

- `canonicalizeUrl` 全局删除 `ref`、`source` 与所有 fragment；其中前两者可能属于内容身份，`#/...` 和 `#!/...` 是页面路由而非段落锚点。
- 直接 RSS `fetchWithMetadata` 返回原始 Feed 项；普通网页发现 Feed 预先过滤招聘 URL；`SyncManager.saveRawEntries` 只对 generic 做末端过滤，导致相同内容按订阅入口不同而结果不同。
- manifest 的 `allowedHosts` 仅写入和返回，没有约束实际请求；删除此字段不改变既有公共 URL/robots 校验及平台请求路径限制。未来若需要统一主机策略，必须在实际请求及重定向路径执行。
- 跨提供方相同内容、不同 URL 的合并问题有代码路径证据，但尚无安全的历史迁移契约；先记录待复现和身份别名方案，不对用户数据库猜测关系。
- 新采集仅在 `canonical_identity` 是显式非 URL 命名空间、且旧库恰有唯一匹配时复用原卡片。遇到历史同 ID 多行则不猜赢家；只有 URL 但无共同稳定 ID 的相似标题不合并。
- 无数据库 schema 或已存数据格式变更；连接器 manifest 增加受限的 `entryPolicy` 声明。现有 URL 如因旧规范化已错误合并，无法从保存的卡片反推出被丢弃的参数或 fragment，本轮不做无证据回填。
- 当前有效评估见 [聚合器设计评审](../aggregator-design-review.md)。
