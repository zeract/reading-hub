# 聚合器架构检查与重构记录

检查日期：2026-09-06。

现有 Electron 主进程、IPC、内置连接器、SQLite 和 React 的分层可以保留。问题主要出在跨层工作缺少统一的完成边界，以及界面把旧分页缓存当成有效数据；没有必要重写阅读器或引入新的框架。

## 已确认并修复的问题

| 问题及影响 | 重构后的行为 |
| --- | --- |
| 知乎补充收藏与关注者使用脱离同步任务的回调直接写库；绕过收集范围过滤，暂停、删除或退出后仍可能写入。 | 补充数据进入 `SyncResult`，由宿主统一检查、过滤和提交；同步完成时新增数量包含收藏。补充接口失败仍保留本人内容成功的原有策略。 |
| 卡片、提取规则、元数据版本、维护标记、游标、成功状态和事件分别写入；后续步骤失败会留下部分提交。 | 网络完成后进入同步 SQLite 事务；任一步失败整体回滚，再单独原子记录失败状态和事件。 |
| 成功响应检查用户修改，失败响应却直接覆盖最新状态；旧网络错误可能把已暂停来源改回错误状态。 | 成功和失败使用同一有效性检查，覆盖删除、暂停、类型、账号、收集范围及提取规则变更；暂停来源在抓取前即拒绝同步。 |
| 同域串行没有合并同来源的重复刷新，调度快照也可能在等待期间失效。 | 同来源共享进行中的任务；失败后允许重试；后台任务开始前重新核对状态和下次刷新时间。同域串行及后台并发上限 2 保留。 |
| 窗口关闭不代表主进程异步工作结束；SQLite 可能先于 IPC 和连接器关闭。 | 退出先停止调度及 IPC 接入，收尾已进入的 IPC，取消排队同步并等待活跃连接器，最后关闭 SQLite。重复退出只清理一次；登录完成回调在释放数据库前解除。 |
| 切换来源连接器后保留旧协议的游标与元数据版本。 | 仅在类型切换时清除协议游标与版本；重命名、调整刷新间隔等保留同步进度。 |
| 翻到第二页以后只刷新第一页并合并旧列表；删除、已读和收藏筛选变化无法清除旧页卡片。 | 按已加载页数重新读取数据库的有界分页，整体替换有效结果，保留已加载历史范围；刷新、翻页和导航共用过期响应检查。 |
| 后台列表刷新拒绝未被处理，且“今日”查询日期被长期缓存。 | 保留现有列表并显示可重试的错误，后台拒绝被接住；刷新重新计算当天日期，跨午夜后更新范围。 |
| 同步错误仅处理 Bearer，URL 参数及具名密钥可能落入错误记录；知乎直接返回任意远端错误正文。 | 审计和同步复用诊断脱敏模块；知乎使用受控状态提示，避免回显远端错误正文。审计脚本也切换到共享模块。 |
| X 授权连接器接收完整数据库和密钥服务对象。 | 生产装配只传入账号读写、账号状态及连接器密钥读写方法，内容持久化继续由宿主控制。内置适配器契约明确不是第三方代码沙箱。 |

## 保留的边界

- 不改变数据库表结构，不对本机订阅和内容进行迁移、清理或远端同步。
- 保留本地优先、Keychain、独立知乎登录分区、公开 URL 校验、robots、网络限流、正文净化及受限原文窗口。
- 保留卡片规范化、跨来源去重、已读/收藏状态、发布时间排序以及每页 100 条的 IPC 读取预算。
- 删除旧的 `createPostSyncWorkflow` 后台写入分支；原审计脱敏模块移为共享诊断模块，没有保留重复实现。

## 限制与取舍

- 本次没有修改正文提取、公式解析、图片代理或阅读器渲染管线，未运行访问全部已订阅来源的 `audit:reader`；视觉审计使用确定性夹具，不等同于实时网站兼容性验证。平台鉴权失败使用模拟响应验证，没有读取真实凭证或调用真实账号接口。
- 退出采用等待活跃连接器结束的策略，没有为所有连接器增加贯穿每次请求的取消信号；慢接口及其现有超时会延迟退出。这样可以保证仍在工作的账号逻辑不会访问已关闭的数据库。
- 列表刷新成本与用户已加载页数成正比；每次 IPC 仍为有界分页，不把整库内容传到渲染器。跨多次 IPC 的分页不是数据库快照；同步期间变化会在后续刷新中校正。
- 构建保留原有的超过 500 kB 的 renderer chunk 提示；本次没有为压制提示改动打包策略。
- 本次未增加新的长期协作规则，因此 `AGENTS.md` 无需修改。主进程和渲染器均有修改，使用新代码需要重启开发应用。
