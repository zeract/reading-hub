## 当前设计与修改

| 根因 | 修改后的契约 |
| --- | --- |
| 删除来源同时删除独有文章，订阅与本地阅读资产绑定。 | `subscriptions.subscribed` 表示是否订阅；取消订阅立即取消同步、停止轮询，保留内容、收藏和来源关系。已取消来源可在侧栏重新订阅。旧删除 IPC 兼容为取消订阅。 |
| 卡片删除不可撤销，校准或维护可能再次清除用户保留的内容。 | 删除写入墓碑并隐藏卡片，支持即时撤销和“最近删除”恢复，重启后仍有效。清理来源仅隐藏独有且未收藏的卡片；校准和共享维护原语保留收藏、墓碑记录及跨来源关系。 |
| 点击卡片就标为已读，加载失败也从未读列表消失。 | 只有当前文章成功进入 React DOM 后才自动标为已读。失败、过期响应和仅打开受限原文窗口不计为已读；随后手动标为未读不会被立即覆盖。 |
| 发布时间与发现时间混用，历史回填干扰新内容列表。 | 默认“新收集”按首次入库时间与 ID 稳定分页；公开归档补回的历史条目标记为 `history`，单独查看。重复同步不重写首次收集时间或类别。“今日发布”只使用真实发布时间，未知日期不会冒充今日发布。 |
| 搜索强制选择单个来源，无法找回其他订阅或已取消来源中的内容。 | 全局与来源视图共用数据库元数据搜索；支持标题、作者、摘要，保留 LIKE 字面量转义和每页数量限制，不增加全文索引或正文持久化。 |
| 来源出错难以发现，类型和账号入口占据普通添加流程。 | 侧栏显示异常状态，来源列表提供设置入口；设置显示错误、最近成功时间、下次检查时间以及相应操作。公共链接为默认添加入口，账号/作者与类型调整逐层展开，共享能力模型约束刷新及恢复入口。 |
| 订阅和来源分别维护连接器、账号及配置，存在双重权威。 | 订阅是连接器元数据的写入权威；SQLite 触发器维护旧来源列的兼容投影，现有只读脚本仍可使用来源结构。来源类型切换同时清除旧账号、配置和协议游标。 |
| 每 15 秒重读已加载页面，空闲成本随历史翻页增长。 | 事务提交后发送版本通知，渲染器合并通知并刷新有效页面；每 60 秒只检查轻量版本和跨午夜边界。保留导航、翻页、异步旧响应的保护及错误重试。 |
| 退出只等待连接器，慢网络和分页延迟关闭。 | 同步上下文携带取消信号，贯穿 HTTP、响应正文、分页、重试等待和后台窗口。取消不记为失败、不推进游标；退出停止接入、取消任务、等待清理，最后关闭数据库。 |
| 学术来源未配置的提供方被计为成功；X 返回的异步请求未进入账号失效处理。 | 只统计实际配置的学术提供方；全部失败正确报错。X 等待异步结果，401 标记账号失效，403 与取消不冒充令牌失效，临时刷新网络失败不强制清除账号状态。 |
| 阅读审计打开正式数据库也会执行新版迁移。 | 审计先通过 SQLite 只读连接和 backup API 创建包含 WAL 的一致快照，仅迁移临时副本并在结束时清理。 |
| 全来源审计发现已渲染 KaTeX 的注释源码在净化后泄漏。 | KaTeX 与 MathJax 共用显式 TeX 注释恢复路径，重新安全渲染；不信任原站样式、不猜测普通文本、不转换代码块。 |

## 后续迭代：账号凭证与并发同步

2026-09-07 检查 X 连接器时发现，来源级同步排队不能保证账号凭证操作互斥。多个来源可以同时读取同一份过期凭证并重复刷新；旧 API 请求迟到的 401 响应也会直接使已经更新的账号失效。两个回归用例在原实现上均实际失败：一次并发同步发出两次刷新，旧 401 将替换凭证后的账号标成 `expired`。

修改将凭证读取、刷新、重新授权写入和失效检查统一放入按 X 账号身份串行执行的流程。进入流程后重新读取账号配置，避免用同步开始时的旧配置覆盖新配置。API 401 仅在当前 Keychain 访问令牌仍与失败请求相同的情况下更新账号状态，令牌比较只发生在内存中。

取消等待中的订阅会立即结束它自己的等待，不允许后续任务越过仍在执行的前序写入；已开始的网络刷新沿用取消和超时逻辑。不可取消的 Keychain 写入会完成后再释放顺序，确保后续订阅读到保存后的凭证。重新授权保存使用同一流程，避免被在途旧刷新覆盖。队列完成后释放内存，不持久化凭证或排队任务。

验证：新增 10 项测试，覆盖共享账号并发、旧 401、排队取消、在途取消、Keychain 写入期间取消、临时失败重试、刷新 400/401、最新账号配置，以及重新授权与刷新交错。全量 `npm test` 为 60 个文件、422 项通过；`npm run build`、`git diff --check` 通过。仍有既有的 renderer chunk 大小提示。

本次仅修改主进程 X 连接器和依赖注入，没有改变 IPC、URL 边界、正文处理或界面，因此未重复运行 style、visual、reader 审计。测试使用内存数据库、模拟 Keychain 和合成令牌，未调用真实 X 账号。串行约束作用于本应用进程；远端已经接收刷新但网络中断等结果不确定情形仍按原有错误与重新授权流程处理。需要重启开发应用，不新增数据库迁移。

## 后续迭代：增量分页与关注列表缓存

2026-09-07 检查同步游标发现两个问题：普通轮询也重写 `followingRefreshedAt`，使持续运行的应用可能永远不刷新关注列表；帖子接口只读第一页就提交最新 ID，导致超过一页的新增帖子被后续 `since_id` 排除。成功返回空关注列表时则存在相反的问题，每轮都重新请求列表。

已依据 [X 用户帖子接口](https://docs.x.com/x-api/users/get-posts)和[分页契约](https://docs.x.com/x-api/fundamentals/pagination)修正。关注列表仅在实际获取成功时更新刷新时间，空列表也按相同期限缓存。分页按账号 ID 去重，重复游标或超过保护上限会报错，不保存不完整列表。

关注订阅和单作者订阅共用帖子分页逻辑。每轮每位作者仍读取一页；增量页未读完时，将后续页游标与已见最大 ID 写入现有 checkpoint，并保留原 `since_id`。最后一页成功后才推进起点，因此分页过程中失败、取消或重启不会跳过剩余内容。续页返回 400 时最多重试一次不带页游标的原增量查询，已有卡片由数据库去重；其他 HTTP 失败沿用原有失败退避和授权状态处理。

首次订阅仍仅获取最新一页，不扩大为全历史抓取。分页进度是普通同步元数据，不包含 OAuth 访问或刷新令牌；无需数据库迁移。升级前已被旧游标跳过的帖子不能据此自动找回，远端接口可访问范围与额度限制仍有效。积压增量通过后续轮询逐页补齐，首次范围和跟踪上限已补充到 README。

验证：最初 4 项回归在旧代码上均实际失败；最终新增 11 项测试，覆盖刷新期限、空列表缓存、两种订阅分页、SQLite 重启恢复、429 失败后重试、页游标拒绝后重放、大整数 ID、过滤回复、初始收集范围、重复游标和取消。全量 `npm test` 为 61 个文件、433 项通过；`npm run build` 与 `git diff --check` 通过，既有 renderer chunk 提示保留。测试未使用真实凭证或调用真实 X 账号；未修改 UI、阅读器和正文处理，因此不重复运行 style、visual、reader 审计。需要重启开发应用。

## 后续迭代：学术作者身份与搜索状态

2026-09-07 检查作者发现流程发现，没有 ORCID 的结果按姓名合并，可能把同一数据库中的同名作者覆盖掉，或把不同数据库中的两个人合成一个订阅。覆盖后还可能留下首条结果的 `targetId` 和另一条结果的作者配置。搜索接口失败则被吞成空结果；界面在改名、请求失败或旧响应迟到时可能仍展示旧作者供选择。

修改后的身份契约：按提供方作者 ID 去重；姓名只用于显示；只有相同有效 ORCID 且每个数据库至多一个候选 ID 时才合并。冲突组保留所有独立选项，避免当前单 ID 订阅结构丢失作者。ORCID 格式和 MOD 11-2 校验位遵循[官方标识结构](https://support.orcid.org/hc/en-us/articles/360006897674-Structure-of-the-ORCID-Identifier)，通过校验仅表示格式合法，并不证明远端归属声明一定正确。搜索结果标题显示数据库、作者 ID 和可用论文数量。

搜索全部成功才能将空结果视为有效；没有候选结果且有提供方失败时返回可操作错误，畸形成功响应同样不冒充空结果。有可用候选时保留健康提供方结果。界面在编辑姓名和发起搜索时清除旧结果，并按请求版本丢弃过期结果与错误；执行中的请求不重复提交。

验证：4 项作者发现回归与 2 项真实 React 状态回归在修复前均失败。最终新增 14 项测试，覆盖同名、冲突、合法/非法 ORCID、重复提供方 ID、空搜索、部分故障、异常响应及过期界面结果。原有 API 路径测试的无效 ORCID 占位值改为官方合法示例。全量 `npm test` 为 63 个文件、447 项通过；构建、`git diff --check`、`audit:style`、`audit:visual`、`audit:renderer` 均通过。

真实 React 审计额外覆盖 20 个作者结果与长名称在 1024、1280、1440（125%）和 1720 窗口中的显示、横向边界及纵向滚动；人工查看窄窗口与 125% 截图。完整视觉审计继续覆盖侧栏、全屏、图片、表格、代码和公式。Electron 在受限沙箱中的首次启动 SIGABRT，使用获准的临时审计环境后通过。截图和模拟数据仅写入系统临时目录。

本轮不修改正文提取或阅读器渲染，未重跑联网 reader 审计；此前远端图片限制及 renderer chunk 构建提示仍在。没有自动修改既有学术订阅或推断其是否属于误合并，历史误选需要用户重新选择正确作者。一个提供方出错时有结果的搜索仍可能是不完整结果集。没有调用真实账号或添加凭证持久化，无需数据库迁移，需要重启开发应用。

## 后续迭代：统一资源排队与等待取消

2026-09-07 检查同步调度发现，同站点的排队任务即使已取消，仍需等前一个慢任务结束才能返回。X 凭证流程已有独立的可取消等待实现，两套排队代码的语义已经分歧。新增集成用例先阻塞第一个来源，再取消第二个来源；旧代码确实无法在第一个来源释放前结束第二个请求。

将既有 X 凭证排队实现提取为 `KeyedTaskQueue`，同步调度按主机名、X 凭证按账号身份分别使用独立队列实例，删除两处被替代的实现。共享契约为：同键先进先出，不同键并行；取消等待者立即结束其等待，但不能让后续任务越过活跃前序任务；任务开始后由任务自身处理网络取消，资源占用持续到实际任务结束。这样不会因取消信号提前释放 Keychain 写入或数据库相关工作的互斥保护。完成后的键与监听器会清理。

## 后续迭代：X 令牌结构与可选轮换

## 后续迭代：API 重定向与凭据边界

2026-09-07 检查带凭据的请求发现，X 和学术接口只校验初始地址，JSON 请求与 AI 请求随后由 fetch 自动跟随重定向。两个回归在旧实现上失败：请求未指定手动重定向；指向私网的 307 未被传输层拒绝。自动跨域重定向虽会移除 Authorization，但 307/308 可继续携带 POST 请求体，OAuth 参数和 AI 摘录因此需要独立的目标范围限制。

## 后续迭代：本地 AI 输出的字节边界与消息边界

2026-09-07 检查本地 AI 子进程传输发现，App Server 与 exec 兼容路径都对每个 stdout 块直接执行 UTF-8 解码，再把整个缓存截断后拆行。操作系统的块边界不是字符或消息边界：多字节字符跨块时会被替换为乱码；一个大块携带多条合法消息时，靠后的回答或完成事件可能被丢弃。四项模拟子进程回归在旧实现上全部失败，分别覆盖两条传输的逐字节中文/emoji 与合并大块消息。

抽取 Utf8LineDecoder，先按换行字节分帧，再一次性解码完整 UTF-8 行；两条路径共享该实现。解码器支持 CRLF、无末尾换行的最后一行、显式丢弃和终止后的迟到数据。只保留未完成行，使用增长缓冲区，避免一字节一块造成大量碎片对象或小片段保留整块内存。单行协议上限与可见答案上限分开：协议行最多 1 MB，可见文本仍最多 40,000 个 JavaScript 字符单位，允许合法 JSON 转义及元数据的额外空间。该限制不是对整个持久连接的累计数据量限制。

超长未完成行立即释放缓冲、返回固定错误并请求终止子进程；App Server 同时拒绝该桥接的待处理请求，下一次请求可以创建新桥接。错误不包含协议原文或本地诊断。取消、超时和关闭也丢弃兼容路径的未完成行。保留既有 SIGTERM 终止策略，本轮未增加对忽略终止信号的子进程的强制回收机制。

## 后续迭代：本地 AI 子进程的有界退出

2026-09-07 继续检查进程所有权，复现 exec 兼容路径取消与超时后只发送 SIGTERM、永久等待 close 的问题。两项旧实现回归均失败：测试进程即使把 killed 标记设为 true，只要没有退出事件，请求仍不结束。App Server 的 stdin 断连处理还会直接移除子进程引用，应用服务原本也没有等待本地 AI 子进程的关闭流程。

新增 ChildProcessScope，统一持有本应用明确注册的子进程对象。停止先请求 SIGTERM，1 秒宽限期内未确认退出则请求 SIGKILL，并释放本应用的 stdio 管道；不把 killed 当作退出证据。自然 exit 与 stdio close 分开处理，保留正常完成的末尾输出，已退出但管道仍被继承的情形则可以只清理管道而不再次发信号。终止和关闭幂等，清除相关计时器，原生迟到错误保留观察者直至管道关闭。不会枚举或终止任意 PID、进程组、用户自行启动的 Codex 或其他进程。

exec 的取消、超时、超长消息、启动/写入失败统一进入“首个失败—清理—结束”的状态路径，迟到数据不能继续产生增量，也不再依赖 close 才能结束请求。App Server 的显式释放和断连同样先交给所有权作用域清理；旧桥接的迟到失败只释放旧实例，不能误关新桥接。LocalCodexCli 增加关闭信号，在命令发现后的交接和兼容回退前检查取消，关闭后拒绝启动新工作。
