## 2026-09-10 图片重复显示修复

确定性用例复现两条路径：懒加载图片被链接/透明容器包裹时，直接兄弟选择器漏掉对应的 noscript 备用图；正文选取高清 srcset 候选后，封面比对丢失了作者声明的低清候选关系。现在统一解析安全的图片候选，在相邻且不含正文/独立图注的容器中合并备用图并保留替代文本和高清候选；封面只在对应图片确实保留于净化后的正文时省略。网页与 Feed 正文共用这一判断。

边界用例覆盖备用图前置/后置、透明链接嵌套、响应式封面、共享占位图的不同照片、不同查询参数的图片，以及作者在不同正文位置复用的插图。去重不增加网络访问，不复制备用 HTML 的事件或脚本，不采用全文图片全局去重。AGENTS.md 已记录上述图片身份和保留规则。

## 2026-09-11 招聘误收与采集范围修复

新增共享内容资格模块，以招聘分区、JobPosting 微数据或明确的 Ashby 职位地址作为排除证据。DOM 提取和校准预览共用分区判断，JSON-LD、Feed 转换和入库前共用地址判断；该限制仅针对网页文章订阅，不改变直接 RSS 或手动保存的范围。没有基于文章标题中的 jobs/careers 单词过滤，也不禁止正常外链。未知招聘系统仍需页面结构证据，这不是对所有网页语义的无误分类器。

## 2026-09-11 Perplexity 渲染超时与抽检真实性

真实 Chromium 诊断显示 Perplexity 主文档约 1–3 秒返回 HTTP 200，DOM 约 5–7 秒就绪，但附属资源会继续拖延完整 load 事件。原实现必须等整个 loadURL 完成，容易触发 20 秒超时；单纯提前读取也不够，Electron 的隔离世界执行会等待加载停止。现在以 DOM 就绪或完整加载完成作为导航阶段完成条件，保留原有 800 毫秒渲染等待；仍在加载时停止剩余资源，并等待 did-stop-loading 后捕获快照。导航和总任务超时、robots、逐跳公共地址检查、主文档 HTTP 状态与快照一致性检查保持。没有增加超时时间或捕获未确认身份/HTTP 状态的页面。

知乎正文入口复用关注采集的内容 URL 契约，旧的列表/导航地址明确报错；跳转到登录页时提示当前会话未登录，不返回登录 HTML。独立正文审计使用临时 Chromium 配置，默认不继承主应用的知乎登录态；该环境限制不能算作已登录阅读测试。未复制浏览器 Cookie 或修改用户原库。

验证中增加原生永不结束的图片请求夹具，要求仍能在 5 秒内完成 DOM 捕获；同时覆盖取消、任务超时、重定向、错误 HTTP 文档、隔离世界、正文大小和凭据隔离。最后修正阅读器吞掉授权会话错误的问题：没有静态请求错误时，保留渲染会话的具体错误，而非替换为笼统的“没有正文”。最终全套 178 文件、1867 项测试、构建、样式契约及 diff 检查通过；停止加载事件由 62 项相关测试和原生网络检查验证。真实数据库一致副本的 Perplexity 两次同步分别约 6 秒和 7 秒完成，状态恢复 active，规则升级到 7，新增均为 0 条，验证没有重复入库。诊断和复检汇总只写临时目录，不提交正文、数据库、凭据或截图。

全来源复检覆盖 30 来源、59 样本，初次 54 通过；vLLM 一篇历史文章的首图超时，单独复测该来源后两项均通过。用户随后在临时窗口完成知乎登录，来源级最新/历史正文及首图审计两项通过，最新专栏约 9320 字、6 张图、5 个公式均完成渲染；指定苏剑林回答另经授权会话读取，作者匹配。临时登录会话在验证结束后清除。旧卡片标题“知乎关注动态”并不证明链接是列表页，核对后其实际是专栏文章；本任务没有据此删除记录。

合并这些明确的复测证据，原 59 样本有 57 项通过。剩余 Visualinux 和 Detecting non-crashing functional bugs 两篇论文的 DOI 出版站仍返回 HTTP 403，尚未解决，不能宣称线上全部通过；未通过更换样本、删除文章、摘要替代全文或忽略 HTTP 错误改变结果。原始全来源报告 `/tmp/reading-hub-timeout-reader.json` 保留最初失败状态，vLLM 和授权知乎的复测分别保存在独立临时报告中。科学空间、普通网页/RSS 和 AI 公式路径仍由本次科学排版审计及回归用例覆盖；最终四档视觉回归零失败，含 125% 字号、公式、图片、表格、代码、AI、侧栏和全屏。用户所要求的“线上全部通过”在这两项远端访问拒绝解决前未达成。

## 2026-09-11 退出期间 IPC 处理器缺失

`library:revision` 和 `window:is-fullscreen` 都是本地主进程接口。启动代码已有“先注册处理器再加载页面”的约束，但退出时移除所有处理器后，迟到 invoke 会收到 Electron 的 No handler registered；同时 macOS activate、托盘或第二实例仍可重新创建窗口，并使用未清除的 renderer-ready 状态加载页面。用户日志没有时间戳，不能据此确定是哪一个事件触发；上述两条生命周期缺口已分别由窗口单测和真实 preload 复现验证。
