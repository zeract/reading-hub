# Codex 开发与验收

## 产物按风险产生

小型文案、样式等修改可用任务对话和提交描述记录范围与验收，不强制创建文档。普通功能、反复失败的问题和多阶段修改，从 [任务模板](tasks/TEMPLATE.md) 创建一份 `docs/tasks/<task>.md`，开工写目标/证据/验收，工作中更新进度。不要为每个阶段复制一套文件。

跨模块、数据库、正文模型或改写协议变更，还应更新对应长期设计文档：正文首先描述当前有效契约，旧决策移到明确标识的历史章节。文档不能代替测试，不事后编造预先确认的设计。任务完成保留简短记录，禁止提交数据库、原文全文、模型响应或凭据。

## 统一入口

- `npm run verify`：全部本地测试、构建、样式契约及工作流回归；CI 使用同一命令。
- `npm run verify:rewrite`：依次检查提取、协议、持久化/恢复和展示回归，再构建和检查样式。用于影响能够限定到这些路径的改写变更；不替代其他模块的相关测试。
- `npm run verify -- --scope docs`：仅 diff 检查；调用者须确认只有文档变化并完成内容审查。
- `npm run verify -- --visual`，或 `npm run verify:rewrite -- --visual --reader`：显式追加现有视觉/来源审计，复用本次唯一一次构建。在线来源审计仍可能因 robots、登录或网络失败。

范围由任务的实际影响决定，不能因为命令更快就选择较小范围。正文共享管线、发布等情况继续适用 AGENTS 门禁；路径匹配不能自动判断契约风险。纯分析不需要执行验证。

报告写入被 Git 忽略的 `.verification/latest.json`，只记录步骤状态、耗时、平台、提交和源文件内容指纹，不捕获命令正文输出。默认不执行真实模型、在线检查、窗口视觉和发布验证，报告明确记录这些限制。本地展示测试中的 jsdom/静态 HTML 不等同于真实 Electron 窗口验收。

开始时写入 running 报告；步骤失败后停止，后续为 not-run。单项默认 10 分钟超时，来源审计 15 分钟；中断时终止当前进程组。执行期间源文件变化会使结果失败。报告的 passed 仅代表所选范围。源指纹包含 Git 跟踪和未忽略的新文件，不包含构建产物；提交后可凭相同 sourceHash 对照已验证内容，不因提交哈希变化重复执行检查。报告不能证明依赖、操作系统或在线服务此后未改变。

CI 上传报告供核对，现有 Ubuntu CI 不代表 macOS Keychain、安装包、退出流程或运行实例验证。涉及这些路径时另外执行相应检查。当前不增加分支审批，也不改变已授权的 main 推送规则。

## 中文改写分层案例

案例清单的执行来源为 `scripts/verification/plan.mjs`；失效路径会使验证失败。复用已有测试，避免维护相同案例的副本。

| 层 | 核心问题与代表案例 | 不能替代的检查 |
| --- | --- | --- |
| 提取 extraction | 明确 CSS 表格、预格式代码、正文净化；先断言源树确实具有预期语义 | 原站发生变化后的最新/历史核对 |
| 协议 protocol | 完整 JSON、段内引用重组/归属、共享修复预算、检查点；模型替身模拟错误 | 实际供应商返回和自然中文质量 |
| 恢复 persistence | 资产不可变、存储往返、旧格式兼容、取消/恢复 | 授权范围内的实际旧稿修复 |
| 展示 presentation | 原文/改写共用展示、代码/表格/链接和媒体生命周期 | Electron 窗口布局、远端媒体可达性 |

`test/rewrite-layered-contract.test.tsx` 使用自编非私密混合材料，贯穿提取、段落协议、保存读取和共享正文组件；源结构预期独立于生成结果，避免“错误源树往返一致”也算正确。它使用模拟模型，无真实模型用量。现有其他案例覆盖科学内容、博客/RSS、知乎及 AI 回答，完整覆盖由 core 测试提供，局部矩阵不宣称覆盖全部来源。

真实模型评估按授权选择代表样本，分别记录模型/提示版本、请求数、初次成功与修复成功；检查准确性、自然中文和术语一致性。不默认增加模型审阅，不把模拟回放写成真实生成。

## 自动化边界

先稳定上述入口，再按需要添加少量 Codex hook；本次不安装 hook。未来 hook 只检查任务与已有验证证据，不在每次工具调用或结束时重复全套测试，不自动进行额外付费模型调用。AGENTS 负责原则、脚本负责执行、CI 留下可复查结果。
